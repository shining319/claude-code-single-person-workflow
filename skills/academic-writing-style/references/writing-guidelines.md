# 写作指导原则

## 核心原则

### 1. 行文朴素，少用长难句（最高优先级）
不管写什么文章，都要用平实的语言把事情讲清楚。这条原则适用于所有文体、所有模式和两种语言，风格档案也不能放宽它。

**中文：**
- 大多数句子控制在 40 字以内，超过 60 字必须拆开
- 一句里的“的”不超过 3 个，不叠多层定语
- 不写一串逗号连成的长流水句，意思转换的地方用句号
- 不堆砌四字词和成语，不用华丽的比喻、排比和宏大叙事开头

**英文：**
- 平均句长约 15–20 词，单句一般不超过 25 词
- 每句最多一个从句
- 少用被动语态和名词化结构（用 decide，不用 make a decision）

**用词：** 能用常见词就不用书面腔或生僻词。专业术语要解释清楚，不追求“显得高级”。

**拆句方法：** 一句只讲一件事；先写主干，再补细节；长定语改成独立的一句。示例见 `ai-markers.md` 第一部分。

### 2. 自然流畅的叙述
避免机械的结构化标记（如"首先...其次...最后"），让内容自然过渡。段落之间主要通过话题延伸或章节标题来引导。“然而”“此外”“however”这类显式转折词不是禁用词，但不要成为段落开头的固定套路，全文少量使用。

### 3. 个人化但不过度
- 可以使用第一人称（"笔者"、"我"、"from my experience"等），但不要频繁使用
- 技术分析类作业中个人化程度应适当降低，保持相对客观
- 通过具体观察、实例和细节来体现个性，而非单纯的观点表达

### 4. 章节划分清晰
- 使用描述性的章节标题（如"从繁琐到简洁：Spring Boot如何改变Java开发"）
- 标题应概括内容，而非泛泛的"引言"、"分析"、"结论"
- 每个章节内部内容连贯，避免突兀的列表

### 5. 避免过度格式化
- 尽量减少项目符号和有序列表的使用
- 将信息融入段落叙述中，使用自然语言表达（如"关键因素包括性能、可维护性和扩展性"）
- 只在确实需要列举并列要点时才使用列表

### 6. 句式有变化，但以短句为主
- 短句为主，偶尔用中等长度的句子调节节奏，避免单调
- 英文写作：使用常见学术词汇，保持雅思6分左右的难度
- 中文写作：使用地道的中文表达，避免英文直译的句式

## 具体技巧

### 段落衔接方式

**方式一：话题延伸**
前一段末尾引出的概念，在下一段开头继续深化：

```
...这种自动配置机制大幅降低了开发门槛。

自动配置的实现依赖于Spring的条件注解系统...
```

**方式二：对比转折**
多数时候通过内容自然呈现对比，少用"然而"、"但是"等明显的转折词：

```
...Netflix的实践展示了微服务的优势。

这种架构模式也带来了新的挑战...
```

**方式三：问题引导**
通过隐含的问题意识推进内容：

```
...系统性能问题日益突出。

从监控数据来看，最突出的瓶颈在数据库层面...
```

### 避免AI痕迹

完整的中英文 AI 高频词、句式和结构问题清单，以及对应的替换策略，见 `ai-markers.md`。

### 个人化表达的使用时机

**适合使用第一人称的场景：**
- 描述实际经验："笔者在项目中遇到过..."、"from my experience working with..."
- 表达个人观点："我认为这个设计存在..."、"I found that..."
- 案例分析中的反思："如果重新设计，我会..."、"looking back, I would..."

**应保持客观的场景：**
- 技术原理解释："Docker使用Linux内核特性..."
- 文献综述："Smith等人的研究表明..."
- 纯技术分析："该算法的时间复杂度为O(n)..."

### 例子和细节的运用

**具体化描述：**
- 避免："系统性能显著提升"
- 改为："页面加载时间从8秒降到2秒，数据库查询压力下降60%"

**使用真实案例：**
- 避免："许多大公司都在使用微服务"
- 改为："Netflix将单体应用拆分为数百个微服务，整个过程花费数年时间"

**提供背景细节：**
- 避免："数据库性能不佳"
- 改为："商品详情页的查询涉及7个表的关联，产生了大量N+1查询问题"

## 中英文特殊注意事项

### 中文写作
- 正确使用中文标点：逗号（，）、句号（。）、冒号（：）、引号（""）
- 避免英文标点混用，如逗号(,)、句号(.)
- 专业术语可适当保留英文，但不要过多："Spring Boot框架"、"Redis缓存"
- 数字和单位之间保持一致性："5万笔订单"或"50,000笔订单"

### 英文写作
- 使用正确的英文标点：逗号(,)、句号(.)、冒号(:)、引号("")
- 雅思6分词汇水平：prioritize用prefer, demonstrate用show, subsequently用then/later
- 避免过长的复合句，单句一般不超过25词，每句最多一个从句
- 缩写首次出现时应全拼：Object-Relational Mapping (ORM)
- 段落长度适中，每段3-6句话

## 质量检查清单

写作完成后，检查以下要点：

- [ ] 中文句子是否都在 60 字以内、英文句子是否都在 25 词以内？
- [ ] 用词是否平实，没有堆砌四字词、华丽比喻和书面腔？
- [ ] 是否按 `ai-markers.md` 扫描过高频词和句式？
- [ ] 是否避免了"首先...其次...最后"的结构？
- [ ] 是否减少了项目符号和有序列表？
- [ ] 段落之间是否自然衔接？
- [ ] 是否使用了具体的例子和细节？
- [ ] 章节标题是否描述性强且清晰？
- [ ] 第一人称使用是否适度？
- [ ] 标点符号是否符合目标语言规范？
- [ ] 句式是否以短句为主，并有适当变化？
- [ ] 语言是否避免了明显的AI痕迹？
- [ ] 技术术语使用是否准确且一致？
