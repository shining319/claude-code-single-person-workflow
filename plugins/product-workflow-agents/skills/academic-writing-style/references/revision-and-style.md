# 润色改写与风格学习

本文件说明模式 B（修改/润色）和模式 C（风格学习）的详细步骤。模式 A（新写）的流程见 SKILL.md。

所有模式都必须遵守朴素行文的硬约束：少用长难句，用词平实。标准见 `writing-guidelines.md` 第一条。

---

## 模式 B：修改 / 润色

用户提供一份已有稿件，要求修改、润色、改写或降低 AI 痕迹。

### 1. 确认修改档位

用户没有说明时，默认使用轻度润色。

- **轻度润色**：保留原文的章节结构和段落顺序，只修改措辞、句子和 AI 痕迹。适合“帮我润色一下”“去掉 AI 味”。
- **深度改写**：可以调整结构、合并或拆分段落、重写标题。适合“帮我重写”“结构不好，大改一下”。

### 2. 诊断

先读完全文，再按 `ai-markers.md` 列出问题。诊断结果直接告诉用户，格式如下：

```
诊断结果（共发现 N 处问题）

长难句：12 处，最长一句 95 字（第 3 段）
AI 高频词：“值得注意的是” 4 次，“至关重要” 3 次，“综上所述” 1 次
句式：段尾拔高总结 5 处，三项排比 3 处
结构：6 个段落长度几乎一样；正文用了 3 处列表
```

诊断只列事实，不做笼统评价。问题很少时，直接说明并只做少量修改。

### 3. 改写

改写时必须保留：

- 原文的事实、数据、日期和人名
- 原文的引用和参考文献，不增加、不删除、不改编号
- 原文的观点和结论，即使你不同意
- 用户明确要求保留的格式（如学校要求的“一、二、”编号标题）

改写时要做：

- 按朴素标准拆分长句（默认执行，不需要用户单独要求）
- 按 `ai-markers.md` 改写命中的词和句式
- 把正文里不必要的列表改成段落
- 有风格档案时，按档案调整第一人称、衔接方式和标点习惯

不要做：

- 编造原文没有的数据、案例或文献来“丰富内容”
- 为了显得不同而改动已经写得好的句子

### 4. 输出

- 文件名：`<原文件名>-revised.md`，保存在原文件同目录；用户直接粘贴文本时，保存到 `outputs/<project-name>/writing/`
- 修改说明：简短列出主要改动，例如“拆分长句 12 处，删除‘值得注意的是’4 处，第 2 节列表改为段落”
- 用户要求时，可以给出几处改前、改后的对照

## 模式 C：风格学习

用户提供自己以前写的文章，希望新文章或润色结果像自己写的。可以和模式 A 或 B 一起使用。

### 1. 检查样本

- 样本最好是用户本人写的学术作业或报告，文体接近本次任务
- 样本总长度少于约 800 字（英文约 500 词）时，告诉用户：“样本较短，风格判断的可信度有限”
- 样本本身带有明显的 AI 痕迹时，提醒用户，并且不学习这部分特征

### 2. 分析 7 个维度

| 维度 | 记录什么 |
| --- | --- |
| 句长 | 平均句长、最长句长、长短句的比例 |
| 段落 | 每段大约几句，段落长短是否变化 |
| 第一人称 | 用“笔者”“我”“本文”还是“we/I”，大约每千字几次 |
| 衔接方式 | 习惯用哪些连接词，是否常用话题延伸 |
| 标点 | 逗号、分号、括号、破折号的使用习惯；中英文标点是否混用 |
| 词汇 | 用词偏口语还是偏书面；专业术语保留英文的程度 |
| 标题 | 编号方式、标题长短、是否使用描述性标题 |

每个维度都要从样本中摘一两句原文作为依据。

### 3. 生成风格档案

保存为 `outputs/<project-name>/writing/style-profile.md`，结构如下：

```markdown
# 写作风格档案

样本：<文件名或简短描述>，共约 N 字
可信度：高 / 中 / 低

## 风格特征
- 句长：平均 22 字，很少超过 40 字。例句：“……”
- 第一人称：用“笔者”，每千字约 2 次。例句：“……”
- ……

## 写作时遵循
- （根据特征整理出的具体做法）

## 与朴素原则的冲突
- （样本中与朴素原则冲突的习惯，写作时不采用）
```

之后的写作都先读取这个档案。用户可以直接编辑档案来调整风格。

### 4. 优先级

1. 学校或老师的格式要求（编号、字数、引用格式等）
2. 朴素行文硬约束（任何情况下都不放松）
3. 用户风格档案
4. 本 skill 的默认风格

示例：用户习惯写 80 字以上的长句，档案里记录这一点，但写作时仍然拆成短句，并在“与朴素原则的冲突”中注明。用户习惯用“一、二、三”编号标题，这不违反朴素原则，按用户习惯来。
